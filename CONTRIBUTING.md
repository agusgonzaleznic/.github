# Contributing

Thanks for thinking about contributing. This guide applies to every public repository under
[github.com/agusgonzaleznic](https://github.com/agusgonzaleznic) that doesn't have a contributing
guide of its own.

## Before you start

- For a small fix, such as a typo or an obvious bug, go ahead and open a pull request.
- For anything bigger, please open an issue first, so we can agree on the approach before you
  spend time on it.
- Each repository's README has its build and test steps, and any rules of its own (a repository
  with many keeps them in `docs/development.md`). Please run the steps before you open a pull
  request.

## Pull requests

- Keep to one change per pull request.
- Fill in the two sections of the pull request template: what changed, and how you verified it.
  Tick only the boxes that are true: an unticked box with a note says more than a false tick.
- Write commit messages in the imperative ("Add the form", not "Added the form"), and say why the
  change is needed, not only what it does.
- Sign your commits. The default branch only accepts commits with a
  [verified signature](https://docs.github.com/en/authentication/managing-commit-signature-verification/about-commit-signature-verification),
  and an unsigned commit in a pull request blocks its merge.
- The history stays linear, so I merge pull requests with a squash merge.
- Where a repository runs checks on pull requests, they have to pass before the merge.

## Conduct and security

Please follow the [code of conduct](https://github.com/agusgonzaleznic/.github/blob/main/CODE_OF_CONDUCT.md).
For a security problem, please don't open an issue. Report it privately in the **Security** tab
of the repository, as the [security policy](https://github.com/agusgonzaleznic/.github/blob/main/SECURITY.md)
describes.

Thank you for helping out.
